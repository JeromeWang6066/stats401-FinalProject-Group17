What counts as an overtake?

OpenF1 overtakes are not an on-track passing table. A swap can be a true pass, a pit stop, a retirement, a safety-car shuffle, or post-race bookkeeping. Change the definition first, then look at who passes whom.

19,303 swaps · 88 sessions (70 races + 18 sprints) · 24 grands prix · OpenF1

Dataset

Source data come from OpenF1. src/fetch_openf1.py pulls overtakes, drivers, pit, race_control, laps, and position for each 2023–2025 session_type=Race weekend into data/raw/. src/process_overtakes.py assigns exclusive tag values and writes data/processed/overtakes_tagged.csv.

To build the event-level table, we join each overtake with driver records to add names, abbreviations, teams, and team colours. We also align each event with a lap using lap-start timestamps and flag burst seconds when at least three overtakes occur within the same second of a race.

We compare event times with pit stops for both drivers and mark swaps within ±90 seconds as near_pit. Race-control messages identify safety-car, VSC, and red-flag intervals, while the chequered flag identifies post_race_diagnostic events. The processed table keeps these indicators alongside the combined tag, so overlapping conditions remain visible during analysis.

A true pass is both cars swapping on track during a live race. Lap 1, same-second bursts, and 8-second bounce-backs all count. Pits, retirements, formation laps, post-chequered-flag events, and unlapping under a safety car do not. Filters use familiar grand prix names (grand_prix: Shanghai / Monaco / Miami), not Catalunya / Monte Carlo.

View 1 uses each race’s first and last positions from position.json (grid / finish), plus Jolpica year-end driver standings. View 3’s season bump uses after-round standings from the same API; the single-race bump aligns that session’s position with laps. Fuller field notes are in processed-overtake-data.html.

Interaction Plan

Interim does not require all five views to be interactive, but each view should say what we add next and why.

  1. View 1 network (implemented). Season, multi-select grands prix, swap type, and an edge-weight slider change the definition and test whether the structure still holds. Hover on nodes / edges is details-on-demand and ego highlighting. Goal: under three or more definitions, check whether overtakes stay among a few pairings.
  2. View 2 lap comparison (implemented). Select a season, grand prix, and Race or Sprint; hover a square to inspect the drivers, lap, position, and classification. Goal: compare raw swaps with true passes, especially at the start and during neutralized periods.
  3. View 3 bump (implemented). Pick a season in the card and switch between championship rank and one race’s lap positions; hover a line for name, current lap or round, and rank then. Points / top-N / team / driver filters stay local and do not change view 1. Goal: check whether net-overtake hubs also climb race position or the championship.
  4. View 4 track map (wireframe). Draw the circuit from location x/y and plot overtakes on corners. Goal: are lap-1 clusters all at turn 1.
  5. View 5 session mix (wireframe). Exclusive-tag donut; click on_track to expand lap1 / burst / bounce. Goal: how much of one session’s OpenF1 overtake count is bookkeeping.

Evaluation Plan

We will evaluate whether the visualization helps viewers distinguish genuine passes from position changes caused by pits or neutralized periods, following Task → Encoding → Interaction → Performance.

  • What: Test whether viewers can compare raw and cleaned swaps, retrieve a specific pass, and identify an unusual cluster (Task); read bar heights, colors, and network edge widths correctly (Encoding); and use filters and tooltips to resolve dense or ambiguous events (Interaction). Measure accuracy and speed (Performance).
  • How: Ask 3-5 classmates to complete the same short tasks without guidance. Observe how they use the charts and controls, check their answers against the tagged data, and ask a brief question after each task.
  • Collect: Record answers, completion times, wrong selections or interpretations, filter and tooltip use, confidence and difficulty ratings, and comments about confusing visual elements.
